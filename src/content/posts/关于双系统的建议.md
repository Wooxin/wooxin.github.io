我现在的主力办公机就是 Nix + Win 双系统。之前是 Arch + Win，再之前是 Ubuntu + Win。双系统这件事，我已经折腾了五六年，该踩的坑全踩了一遍。这篇文章是我个人的经验总结，如果你在考虑装双系统，希望对你有用。

## 你到底需要双系统吗

双系统不是标配，是需求驱动的。先问自己几个问题：

**装个虚拟机不就行了？**

如果你只是偶尔用 Linux 跑个命令、编译个东西、学学命令行，VMware 或 VirtualBox 完全够。快照功能意味着搞崩了十秒钟恢复，比双系统省心一万倍。

但虚拟机有几个硬伤：
- GPU 直通麻烦，跑 CUDA 或者打游戏基本不行
- 磁盘 IO 隔了一层虚拟化，编译大项目慢很多
- 内存被割裂，8GB 的本子开个虚拟机宿主机就卡

如果你有**频繁的本地编译需求、CUDA 开发、或者想把 Linux 当主力用**，双系统才是正解。

**WSL2 不香吗？**

WSL2 在很多场景下确实够用了——VS Code 远程开发、Docker、Node/Python 开发都没问题。但 WSL2 本质是在 Hyper-V 虚拟机里跑的，和裸机 Linux 的区别：

- `systemd` 支持不完整（虽然新版 WSL 有了，但和真 Linux 还是有差距）
- 网络是 NAT 的，搞网络相关的开发和调试很痛苦
- IO 性能和裸机差距明显，尤其是大量小文件的读写场景
- 有些内核模块就是跑不起来

WSL2 适合**开发者**，不适合**运维**。你要折腾 iptables、KVM、Docker in Docker、PXE——老老实实双系统。

**苹果 M 系列芯片用户**

如果你用的是 M 系列芯片的 Mac，Asahi Linux 已经很可用，但劝你别折腾。macOS 本身是 Unix，大部分 Linux 工具都能跑。省下折腾的时间多写几行代码比什么都强。

## 选什么系统

这个看你的阶段和目的。

**新手——Ubuntu / Linux Mint**

如果你之前没碰过 Linux，从 Ubuntu LTS 开始。资料最多，社区最大，出问题一搜就有答案。别一开始就上 Arch——包管理器都没搞明白就去折腾滚动更新，大概率劝退。

```bash
# Ubuntu 一个命令装好大部分开发工具
sudo apt install build-essential git curl vim
```

**进阶——Arch Linux**

如果你想**真的学会 Linux**，Arch 是最好的老师。官方 Wiki 是 Linux 圈最好的文档，没有之一。手动安装的过程会逼你理解分区、引导、内核、initramfs、systemd——这些都是你用 Ubuntu 一键安装永远学不到的。

```bash
# Arch 安装的第一个命令就是分区
fdisk /dev/nvme0n1
# 然后挂载、pacstrap、genfstab、arch-chroot...
# 每一步都在教你 Linux 是怎么启动的
```

**折腾累了——NixOS**

当你装过无数遍 Arch、每次换电脑或者滚挂了都要重配环境，你就会意识到一个问题：**能不能用一份文件描述整个系统？** NixOS 就是这个问题的答案。

我现在的主力就是 Nix + Win。把 `/etc/nixos` 文件夹推到 GitHub，换新电脑 `git clone` 然后一次构建，整个环境就回来了。包括 IDE、Shell 配置、快捷键、字体——全都是声明式的。

```nix
# NixOS 配置示例
environment.systemPackages = with pkgs; [
  vim git curl
  firefox vscode
  gcc gdb cmake
];
```

## 怎么分区

这是双系统最容易被忽略的一步。分坏了轻则重装，重则数据全丢。

**推荐方案：EFI 分区共享 + Linux 独立分区 + 共享数据分区**

```
/dev/nvme0n1
├── nvme0n1p1  EFI (512MB)      ← Windows 和 Linux 共用
├── nvme0n1p2  Windows (你自己定)
├── nvme0n1p3  Linux / (80~120G)
├── nvme0n1p4  Linux /home (剩余大部分)
└── nvme0n1p5  共享数据 (exFAT/NTFS，可选)
```

**关键点：**

1. **EFI 分区要够大**。Windows 默认 100MB，但双系统建议 512MB~1G。Arch 默认的 `mkinitcpio` 生成的 initramfs + 内核就有 50~100MB，加上 fallback 镜像和 Windows 的 bootloader，512MB 是安全下限。

2. **`/home` 单独分区**。这是血的教训——系统和用户数据分离，以后换发行版只需要重装 `/`，`/home` 保留不动。配置文件、SSH 密钥、项目代码全在 `/home` 里。

3. **共享数据分区用 exFAT**。NTFS 在 Linux 上的原生支持虽然比几年前好多了（`ntfs3` 内核驱动），但权限和文件名编码还是时不时出问题。exFAT 两个系统都能完美读写，存电影、音乐、工作文件很合适。

4. **不要动 Windows 的分区**。在 Windows 的磁盘管理里缩 Windows 分区，腾出空间给 Linux。**绝对不要**在 Linux 分区工具里调整 NTFS 分区大小，Windows 的 NTFS 元数据有时候 Linux 检测不到，缩了可能 Windows 起不来。

## 引导怎么做

引导是双系统最头疼的部分之一。Windows 更新会覆盖 EFI 分区、Linux 内核更新会改引导顺序、BIOS 设置莫名其妙恢复默认——这些都遇到过。

**别用 GRUB（如果你追求简单）**

GRUB 太重量级了。一个配置文件几百行，自动生成的脚本绕来绕去，出问题根本看不懂。我只推荐两种引导方案：

**方案一：systemd-boot**

Arch/NixOS 自带，配置超级简单：

```bash
# /boot/loader/loader.conf
default arch
timeout 3

# /boot/loader/entries/arch.conf
title Arch Linux
linux /vmlinuz-linux
initrd /initramfs-linux.img
options root=UUID=xxx rw
```

自动检测 Windows Boot Manager，不需要手动写 Windows 引导项。

**方案二：rEFInd**

如果你想要图形界面选系统，rEFInd 是最佳选择。图标好看、自动扫描所有系统的引导项、不需要手动配置。

```bash
# Arch 安装
sudo pacman -S refind
sudo refind-install
```

安装完自动检测到 Windows 和所有 Linux 内核版本，开机选一下就行。

**方案三：Limine**

非常轻量的引导器，配置文件简单到爆：

```
# limine.cfg
:Arch Linux
PROTOCOL=linux
KERNEL_PATH=boot:///vmlinuz-linux
CMDLINE=root=UUID=xxx rw
```

但 Limine 对多硬盘、NVMe 的兼容性偶尔会出问题，不太推荐新手用。

**无论选哪个引导，Windows 更新后引导被覆盖怎么办？**

这是 Windows 的经典操作——大版本更新会重写 EFI 分区。解决方法：

```bash
# 进 Linux 安装盘 chroot 后重新安装引导
mount /dev/nvme0n1p3 /mnt
mount /dev/nvme0n1p1 /mnt/boot
arch-chroot /mnt
bootctl install   # systemd-boot
# 或者 refind-install
```

或者更简单：别慌，进 BIOS 的 Boot Menu（F12/F2/Del），手动选 Linux 的 EFI 文件启动。Windows 更新只是改了默认启动顺序，没有删文件。

## Windows 和 Linux 共存的小技巧

**关掉 Windows 快速启动**

控制面板 → 电源选项 → 选择电源按钮的功能 → 取消勾选"启用快速启动"。不关的话 Windows 关机其实是"深度休眠"，NTFS 分区在 Linux 下会变成只读。

**时钟同步**

Windows 默认把 BIOS 时间当本地时间，Linux 默认当 UTC 时间。来回切换系统会导致时间差 8 小时。

```bash
# Linux 系修：让 Linux 把 BIOS 时间当本地时间
timedatectl set-local-rtc 1

# Windows 系修（推荐）：让 Windows 把 BIOS 时间当 UTC
reg add "HKLM\SYSTEM\CurrentControlSet\Control\TimeZoneInformation" /v RealTimeIsUniversal /t REG_DWORD /d 1 /f
```

推荐改 Windows，因为 Linux 的 UTC 假设更合理。

**共享 Steam 游戏库**

如果你在两个系统都打游戏，Steam 的游戏库可以共享：

```bash
# Linux 挂载 Windows 的 NTFS 游戏盘
sudo mount -t ntfs3 /dev/nvme0n1p5 /mnt/games
# Steam → 设置 → 下载 → Steam 库文件夹 → 添加 /mnt/games/SteamLibrary
```

但注意：不是所有游戏都能跨系统运行。有原生 Linux 版的最好用原生版，Proton 兼容层跑 Windows 游戏有时候会出反作弊问题。

## 总结

双系统不是目的，是手段。选择它的理由只有一个：**虚拟机满足不了你的需求**。如果你只是学 Linux、跑跑命令行、部署个人项目——开个虚拟机或者 WSL2 就够。

如果你已经决定要双系统：

- EFI 分区给够 512MB
- `/home` 独立分区
- 新手首选 Ubuntu，想学东西上 Arch，折腾够了换 NixOS
- 引导用 systemd-boot，别碰 GRUB
- 关掉 Windows 快速启动，时钟改 UTC
- 重要数据永远在三块盘上有备份——双系统不防删库跑路，不防硬盘坏了，不防手贱 `rm -rf /`
